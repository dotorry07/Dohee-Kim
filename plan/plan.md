# 프로젝트명: 새내기 ON

## 1. 프로젝트 개요

새내기 ON은 성신여자대학교 신입생이 학교생활에 빠르게 적응할 수 있도록 돕는 웹 서비스이다.  
신입생에게 필요한 시간표 관리, 학교 지도, 게시판, 강의평, 주요 공지 확인 기능을 한곳에 모아 제공한다.

## 2. 목표 사용자

- 성신여자대학교 신입생
- 학교 시설, 수업, 공지, 커뮤니티 정보를 한 번에 확인하고 싶은 재학생
- 학과별 정보를 공유하거나 새내기 질문에 답변하고 싶은 선배 재학생

## 3. 핵심 문제

- 신입생은 학교 건물, 강의실, 학사 일정, 공지사항을 따로 찾아야 한다.
- 시간표와 학교 지도를 연결해서 보기 어렵다.
- 강의 정보와 수업 후기를 한눈에 확인하기 어렵다.
- 새내기 질문을 부담 없이 올리고 답변받을 공간이 필요하다.

## 4. 서비스 목표

- 신입생이 첫 학기 동안 자주 찾는 정보를 3번 이하의 클릭으로 확인할 수 있게 한다.
- 시간표, 지도, 공지, 게시판을 연결해 실제 학교생활 흐름에 맞는 화면을 제공한다.
- MVP 단계에서는 기능을 작게 시작하되, 이후 학과별/캠퍼스별 확장이 가능하도록 설계한다.

## 5. MVP 기능 범위

### 5.1 로그인 / 회원가입

#### 기능 설명

- 사용자는 이메일과 비밀번호로 회원가입 및 로그인할 수 있다.
- 회원가입 시 이름, 학과, 학년을 입력한다.
- 로그인한 사용자만 게시글 작성, 댓글 작성, 강의평 작성, 시간표 저장을 할 수 있다.

#### 입력 정보

- 이메일
- 비밀번호
- 이름 또는 닉네임
- 학과
- 학년

#### 주요 화면

- 로그인 화면
- 회원가입 화면
- 내 정보 화면

#### 검증 규칙

- 이메일 형식이 올바르지 않으면 가입할 수 없다.
- 비밀번호는 최소 8자 이상으로 제한한다.
- 닉네임 또는 이름은 필수 입력값으로 둔다.
- 학과와 학년은 선택 목록으로 제공한다.

### 5.2 시간표 생성

#### 기능 설명

- 사용자는 요일, 시간, 강의명, 교수명, 강의실을 입력해 시간표를 만들 수 있다.
- 생성한 시간표는 주간 표 형태로 볼 수 있다.
- 강의실 정보가 있으면 학교 지도 기능과 연결할 수 있다.

#### 입력 정보

- 강의명
- 교수명
- 요일
- 시작 시간
- 종료 시간
- 강의실 또는 건물명
- 메모

#### 주요 화면

- 시간표 목록 화면
- 시간표 추가/수정 화면
- 주간 시간표 화면

#### 우선 구현 범위

- 직접 입력 방식으로 시간표 생성
- 강의 추가, 수정, 삭제
- 시간 겹침 검사
- 로컬 또는 DB 저장

#### 추후 확장

- 수강신청 내역 파일 업로드
- 강의 검색 후 시간표 자동 추가
- 친구와 시간표 공유

### 5.3 시간표 관리

#### 기능 설명

- 사용자는 만든 시간표를 수정하거나 삭제할 수 있다.
- 여러 학기 시간표를 저장할 수 있도록 확장 가능하게 설계한다.

#### 주요 기능

- 강의별 색상 지정
- 강의 메모 작성
- 현재 학기 시간표 보기
- 시간표 삭제 전 확인 알림

### 5.4 학교 지도

#### 기능 설명

- 사용자는 학교 건물과 주요 시설 위치를 확인할 수 있다.
- 건물명, 강의실명, 편의시설명으로 검색할 수 있다.
- 시간표에 입력된 강의실과 연결해 수업 장소를 확인할 수 있다.

#### 주요 장소

- 강의동
- 도서관
- 학생회관
- 식당/카페
- 행정실
- 편의시설

#### MVP 구현 방식

- 정적 지도 이미지 또는 간단한 캠퍼스 약도 기반으로 시작한다.
- 건물 목록을 클릭하면 위치와 설명을 보여준다.
- 실제 지도 API 연동은 추후 확장으로 둔다.

#### 추후 확장

- 네이버 지도 또는 카카오맵 API 연동
- 현재 위치 기반 길찾기
- 강의실까지 이동 시간 안내

### 5.5 게시판

#### 기능 설명

- 사용자는 학교생활 관련 질문이나 정보를 게시글로 작성할 수 있다.
- 게시글에는 댓글을 달 수 있다.
- 게시판은 새내기 질문, 자유게시판, 학과별 게시판으로 나눌 수 있다.

#### 게시판 분류

- 새내기 Q&A
- 자유게시판
- 학과별 게시판
- 정보 공유

#### 주요 기능

- 게시글 작성, 수정, 삭제
- 게시글 목록 조회
- 게시글 상세 조회
- 댓글 작성, 삭제
- 카테고리별 필터
- 제목/내용 검색

#### 운영 규칙

- 로그인한 사용자만 글과 댓글을 작성할 수 있다.
- 작성자 본인만 수정/삭제할 수 있다.
- 신고 기능은 MVP 이후 확장 기능으로 둔다.

### 5.6 강의평 작성 / 확인

#### 기능 설명

- 사용자는 수강한 강의에 대한 평가를 작성할 수 있다.
- 다른 사용자는 강의명, 교수명으로 강의평을 검색할 수 있다.

#### 입력 정보

- 강의명
- 교수명
- 학기
- 평점
- 과제량
- 시험 난이도
- 출석 방식
- 자유 후기

#### 주요 기능

- 강의평 작성
- 강의평 목록 조회
- 강의명/교수명 검색
- 평균 평점 표시

#### 운영 규칙

- 로그인한 사용자만 작성할 수 있다.
- 같은 사용자가 같은 강의에 중복 작성하지 못하게 한다.
- 욕설, 개인정보 포함 글은 신고 대상으로 둔다.

### 5.7 주요 공지사항 보기

#### 기능 설명

- 사용자는 학교 주요 공지사항을 보기 쉬운 형태로 확인할 수 있다.
- 공지는 카테고리, 날짜, 제목, 링크를 중심으로 제공한다.

#### 공지 분류

- 학사
- 장학
- 수강신청
- 행사
- 취업/진로
- 일반

#### MVP 구현 방식

- 관리자가 직접 공지 제목, 요약, 링크를 등록한다.
- 사용자는 최신순으로 공지를 확인한다.
- 중요한 공지는 상단 고정 표시한다.

#### 추후 확장

- 학교 홈페이지 공지 크롤링 또는 API 연동
- AI 공지 요약
- 학과/학년별 맞춤 공지

## 13. 결정 필요 사항

아래 항목은 개발을 시작하기 전에 선택이 필요하다.

1. 개발 목표
   - 학습용 개인 프로젝트인지, 팀 프로젝트인지, 실제 배포까지 목표인지 결정한다.

2. 기술 스택
   - HTML/CSS/JavaScript 중심으로 갈지, React/Next.js 기반으로 갈지 결정한다.

3. 로그인 방식
   - 실제 이메일 인증까지 구현할지, MVP에서는 이메일/비밀번호 로그인만 구현할지 결정한다.

4. 지도 구현 방식
   - 정적 캠퍼스 약도로 시작할지, 처음부터 지도 API를 사용할지 결정한다.

5. 공지사항 제공 방식
   - 관리자가 직접 등록할지, 학교 홈페이지 데이터를 자동 수집할지 결정한다.

6. 사용자 범위
   - 성신여대 전체 학생 대상인지, 특정 학과/새내기 대상인지 결정한다.

7. 강의평 공개 범위
   - 비로그인 사용자도 볼 수 있게 할지, 로그인 사용자만 볼 수 있게 할지 결정한다.

## 15. 사용자 시나리오

### 15.1 신입생 온보딩

1. 사용자가 회원가입 화면에 접속한다.
2. 이메일, 비밀번호, 이름/닉네임, 학과, 학년을 입력한다.
3. 회원가입 완료 후 로그인한다.
4. 대시보드에서 오늘 수업, 주요 공지, 최근 게시글을 확인한다.
5. 시간표가 없으면 시간표 생성 버튼을 보여준다.

### 15.2 시간표 등록

1. 사용자가 시간표 화면으로 이동한다.
2. 강의 추가 버튼을 누른다.
3. 강의명, 교수명, 요일, 시작 시간, 종료 시간, 강의실을 입력한다.
4. 저장 시 같은 요일에 시간이 겹치는 강의가 있는지 검사한다.
5. 문제가 없으면 주간 시간표에 강의 블록을 표시한다.
6. 강의 블록을 클릭하면 상세 정보, 수정, 삭제 버튼을 보여준다.

### 15.3 강의실 위치 확인

1. 사용자가 시간표에서 강의 블록을 클릭한다.
2. 강의 상세에서 강의실 또는 건물명을 확인한다.
3. 위치 보기 버튼을 누른다.
4. 지도 화면으로 이동하면서 해당 건물을 선택 상태로 표시한다.
5. 건물 설명과 주요 시설 정보를 함께 보여준다.

### 15.4 게시판 질문 작성

1. 사용자가 게시판 화면으로 이동한다.
2. 카테고리를 선택한다.
3. 제목과 내용을 입력해 게시글을 작성한다.
4. 다른 사용자는 게시글을 읽고 댓글을 작성한다.
5. 작성자는 본인의 글과 댓글을 수정 또는 삭제할 수 있다.

### 15.5 강의평 확인

1. 사용자가 강의평 화면으로 이동한다.
2. 강의명 또는 교수명으로 검색한다.
3. 강의별 평균 평점과 후기 목록을 확인한다.
4. 로그인한 사용자는 강의평 작성 버튼으로 후기를 남긴다.

## 16. 화면별 상세 요구사항

### 16.1 대시보드

#### 표시 정보

- 오늘 날짜
- 오늘 수업 목록
- 상단 고정 공지 3개
- 최근 게시글 5개
- 최근 강의평 5개

#### 빈 상태

- 시간표가 없으면 "시간표를 먼저 만들어보세요" 안내와 생성 버튼을 표시한다.
- 공지가 없으면 "등록된 공지사항이 없습니다"를 표시한다.
- 게시글이 없으면 "아직 작성된 글이 없습니다"를 표시한다.

#### 완료 기준

- 로그인 여부에 따라 표시 정보가 달라진다.
- 모바일에서도 주요 정보가 세로 흐름으로 자연스럽게 보인다.

### 16.2 로그인 / 회원가입

#### 화면 요소

- 이메일 입력
- 비밀번호 입력
- 비밀번호 확인 입력
- 이름 또는 닉네임 입력
- 학과 선택
- 학년 선택
- 가입/로그인 버튼
- 오류 메시지 영역

#### 오류 메시지

- 이메일 형식이 올바르지 않습니다.
- 비밀번호는 8자 이상이어야 합니다.
- 이미 가입된 이메일입니다.
- 이메일 또는 비밀번호가 올바르지 않습니다.

#### 완료 기준

- 회원가입 후 로그인 화면으로 이동한다.
- 로그인 성공 후 대시보드로 이동한다.
- 로그인한 사용자는 새로고침 후에도 로그인 상태를 유지한다.

### 16.3 시간표

#### 화면 요소

- 요일 헤더: 월, 화, 수, 목, 금
- 시간 축: 09:00부터 18:00까지
- 강의 블록
- 강의 추가 버튼
- 강의 수정/삭제 모달

#### 비즈니스 규칙

- 종료 시간은 시작 시간보다 늦어야 한다.
- 같은 요일의 시간대가 겹치면 저장할 수 없다.
- 강의명, 요일, 시작 시간, 종료 시간은 필수값이다.
- 교수명, 건물명, 강의실, 메모는 선택값이다.

#### 완료 기준

- 강의를 추가하면 시간표에 즉시 반영된다.
- 강의를 수정하면 기존 블록이 갱신된다.
- 강의를 삭제하면 시간표에서 사라진다.
- 겹치는 시간 입력 시 저장을 막고 오류 메시지를 보여준다.

### 16.4 학교 지도

#### 화면 요소

- 캠퍼스 약도 영역
- 건물/시설 검색 입력
- 장소 카테고리 필터
- 장소 목록
- 선택한 장소 상세 패널

#### 장소 상세 정보

- 장소명
- 건물명
- 층
- 설명
- 관련 태그

#### 완료 기준

- 장소 목록에서 항목을 클릭하면 지도 위 선택 표시가 바뀐다.
- 검색어를 입력하면 장소 목록이 필터링된다.
- 시간표에서 전달된 건물명이 있으면 해당 장소를 우선 선택한다.

### 16.5 게시판

#### 화면 요소

- 카테고리 탭
- 검색 입력
- 게시글 목록
- 게시글 작성 버튼
- 게시글 상세
- 댓글 목록
- 댓글 입력창

#### 게시글 목록 표시 정보

- 카테고리
- 제목
- 작성자 닉네임
- 댓글 수
- 조회 수
- 작성일

#### 완료 기준

- 게시글 목록은 최신순으로 정렬된다.
- 카테고리 필터와 검색이 동작한다.
- 작성자 본인에게만 수정/삭제 버튼을 보여준다.
- 비로그인 사용자가 작성 버튼을 누르면 로그인 화면으로 이동한다.

### 16.6 강의평

#### 화면 요소

- 강의명/교수명 검색 입력
- 강의평 목록
- 평균 평점
- 강의평 작성 버튼
- 평점 선택
- 과제량 선택
- 시험 난이도 선택
- 출석 방식 선택
- 자유 후기 입력

#### 완료 기준

- 검색어에 따라 강의평 목록이 필터링된다.
- 평균 평점은 해당 강의평 목록 기준으로 계산된다.
- 같은 사용자는 같은 강의명과 교수명 조합에 한 번만 작성할 수 있다.

## 18. 데이터베이스 제약 조건

### User

- email은 unique로 설정한다.
- role 기본값은 user로 설정한다.
- grade는 1, 2, 3, 4 중 하나로 제한한다.

### Timetable

- userId는 User.id를 참조한다.
- 사용자별 기본 시간표를 하나 지정할 수 있도록 isDefault 필드를 추가할 수 있다.

### ClassSchedule

- timetableId는 Timetable.id를 참조한다.
- dayOfWeek는 MON, TUE, WED, THU, FRI 중 하나로 제한한다.
- startTime, endTime은 HH:mm 형식으로 저장한다.
- 같은 timetableId 안에서 dayOfWeek, startTime, endTime 겹침을 애플리케이션 로직에서 검사한다.

### BoardPost

- userId는 User.id를 참조한다.
- category는 freshman, free, department, info 중 하나로 제한한다.
- title은 1자 이상 100자 이하로 제한한다.
- content는 1자 이상 5000자 이하로 제한한다.

### CourseReview

- rating은 1부터 5까지 허용한다.
- assignmentLevel과 examLevel은 low, medium, high 중 하나로 제한한다.
- userId, courseName, professorName 조합은 unique로 설정한다.

### Notice

- category는 academic, scholarship, registration, event, career, general 중 하나로 제한한다.
- sourceUrl은 선택값이지만, 입력된 경우 URL 형식을 검증한다.

## 19. 추천 MVP 확정안

선택이 아직 없다면 아래 기준으로 먼저 구현한다.

- 개발 목표: 학습용이지만 실제 배포 가능한 수준의 웹앱
- 기술 스택: React + Node.js + Express + SQLite
- 로그인: 이메일/비밀번호 로그인, 이메일 인증은 제외
- 지도: 정적 캠퍼스 약도와 장소 목록 기반
- 공지사항: 관리자 직접 등록 방식
- 사용자 범위: 성신여대 신입생 중심, 재학생도 사용 가능
- 강의평 공개 범위: 비로그인 사용자도 읽기 가능, 작성은 로그인 필요

## 24. 완료 정의

프로젝트 MVP는 아래 조건을 만족하면 완료로 본다.

- 사용자가 회원가입, 로그인, 로그아웃을 할 수 있다.
- 로그인한 사용자가 시간표를 생성하고 강의를 관리할 수 있다.
- 시간표에서 겹치는 강의 등록을 막는다.
- 사용자가 학교 장소를 검색하고 위치 정보를 확인할 수 있다.
- 사용자가 주요 공지사항을 최신순으로 확인할 수 있다.
- 사용자가 게시글과 댓글을 작성할 수 있다.
- 사용자가 강의평을 검색하고 작성할 수 있다.
- 작성자 또는 관리자 권한이 필요한 기능은 권한 검사를 통과해야 한다.
- 모바일과 데스크톱에서 주요 화면이 깨지지 않는다.
